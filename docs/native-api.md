# GSystem native scripting API

Generated by `tools/nativeapi.mjs` + `tools/nativeapi-md.mjs` from the Ghidra v2 pseudocode of `GSystem.dll`
(Cities in Motion 1.0.22) and its MSVC RTTI (`tools/rtti.mjs`). Machine-readable data: `docs/native-api.json`,
`docs/rtti-classes.json`. Handler/registrar addresses point into `decompiled/GSystem-v2/functions/0x<addr>.c`.

## How the engine exposes things to scripts

* **Globals** are inserted into one name→variant map (`FUN_1000f5f0`). Functions are `gsOpaqueFunction` /
  `gsTransparentFunction` objects holding a C handler and an argument range; constants are value variants.
* **Class members** are declared by each class's virtual `registerMembers()` (vtable slot 30, offset `0x78`), run once
  per class by `FUN_1001c2a0`, which first calls the parent class's registrar. Fields bind directly to an object offset
  (`gs*FieldVariant`); methods carry a handler and argument range; events are slots scripts bind with `event obj.x::(...)`.
* Field types (registrar → type code): bool 2 (`FUN_1001bff0`), int 3 (`FUN_1001c020`), float 4 (`FUN_1001c050`),
  str 5 (`FUN_1001c080`), wstr 6 (`FUN_1001c0b0`), custom 7 (`FUN_1001c0e0`), var 8 (`FUN_1001c120`), bit 9 (`FUN_1001c160`);
  methods `FUN_1001c1a0`, events `FUN_1001c200`. Every script object also has `gsObjectVariant`'s built-ins.
* Field callbacks (descriptor `+0x10` / `+0xc`, built by `FUN_1001bf50`): a **setter** replaces the plain store; the
  setter `FUN_1001bfc0` throws, which marks the field **read-only** (*ro*); a **hook** is called by the default store
  path (`FUN_1001cc40`) before the value is assigned. In the tables: `set=` setter, `hook=` hook.

## Coverage

* 131 global functions, 336 constants, 72 script classes with 833 members
  (440 fields, 297 methods, 96 events).
* Cross-checked against identifiers used by the 3 601 shipped scripts: every native global function, constant and
  member they use is present here (the usage scan's only misses were false positives such as `unlock`/`dds`, which are
  script-defined).
* Not covered: argument *types* and semantics (handlers are listed, not yet read); members created dynamically at run
  time; the exported C embedding API (`registerFunction`, `registerConstant`, … — see the main report).
